# 接入指南

> 面向要接入 PASM Omni 的开发者与实施同学。**产品源码不公开**，本指南描述的是对外接口与配置方式。

---

## 一、部署与启动（私有化交付）

交付包解压后，在一台装有 **Python 3.11+** 的机器上运行即可（**无需安装任何第三方依赖**）：

```bash
# 灌入示例知识（可选，用于快速验证）
pasm-omni --db customer.db seed

# 启动 HTTP 服务（默认 8770）
pasm-omni --db customer.db serve --port 8770

# 确认当前生效的大脑
pasm-omni --db customer.db brain
```

启动后：

| 地址 | 用途 |
| --- | --- |
| `http://<host>:8770/` | 坐席工作台 |
| `http://<host>:8770/widget.js` | 网页挂件脚本 |

## 二、账号与鉴权模式（**上线前必读**）

系统有两种模式，由「有没有创建过账号」自动决定：

| 模式 | 触发条件 | 行为 |
| --- | --- | --- |
| **兼容模式** | 一个账号都没有 | **不做鉴权**，所有接口开放 |
| **强制鉴权模式** | 已有任意账号 | 读/写接口一律要求身份，按角色授权 |

> ⚠️ **兼容模式只能部署在可信内网。** 面向公网请先创建管理员账号进入强制鉴权模式。

角色分三级：`viewer`（只读）/ `agent`（日常操作）/ `admin`（审核、审计、授权）。

## 三、网页挂件（一行接入）

在任意页面加一行：

```html
<script src="https://<你的域名>/widget.js"
        data-api="https://<你的域名>"
        data-title="在线客服"
        data-greeting="您好，有什么可以帮您？"></script>
```

可选属性：

| 属性 | 说明 |
| --- | --- |
| `data-api` | 后端地址（挂件与后端不同域时必须显式指定） |
| `data-title` | 面板标题 |
| `data-greeting` | 欢迎语 |
| `data-lang` | 语言 |

挂件特性：纯原生 JS、**不依赖任何前端框架**、**不向任何第三方上传数据**、
访客身份用本地存储记忆（刷新不丢会话）。

## 四、订单接入

### 4.1 Shopify

在 Shopify 后台创建 webhook，指向：

```
POST https://<你的域名>/inbound/shopify
```

主题建议订阅：`orders/create`、`orders/updated`、`orders/fulfilled`、`orders/cancelled`。
验证使用 `X-Shopify-Hmac-Sha256`（HMAC-SHA256 + base64）。

### 4.2 WooCommerce（WordPress）

在 WooCommerce → 设置 → 高级 → Webhook 中创建，指向：

```
POST https://<你的域名>/inbound/woocommerce
```

验证使用 `X-WC-Webhook-Signature`（算法同上）。
物流单号：若安装了提供运单号的插件，会写入订单元数据，系统会自动识别常见键名。

### 4.3 通用端点（其它平台 / 自建站 / ERP）

```
POST https://<你的域名>/inbound/orders/{source}
```

签名头：`X-Omni-Signature`，**同时支持 hex 与 base64（含大写、`sha256=` 前缀）**。
载荷字段支持**别名识别**，例如：

| 语义 | 可接受的字段名 |
| --- | --- |
| 订单号 | `order_no` / `number` / `order_id` / `交易号` |
| 状态 | `status` / `order_status` / `orderStatus` |
| 金额 | `total` / `amount` / `实付金额` |
| 买家 | `email` / `buyer_email` |
| 运单号 | `tracking_no` / `tracking_number` / `运单号` |

> **安全约定**：未配置对应密钥时，**拒绝一切写入**。

### 4.4 订单处理约定

- **幂等**：以「平台 + 订单号」为唯一键，重复投递不会产生重复订单
- **不乱序回退**：迟到的旧事件只会补全空字段，**不会**把「已发货」打回「已付款」
- **不物理删单**：收到删除事件只记录，订单历史作为事实资产保留

## 五、消息接入（主动发消息）

除访客主动发起外，系统支持坐席在工作台主动回复、以及合规前提下的群发：

- **单条回复**：工作台直接发送，或经接口发送
- **群发**：需经过模板审核态 + 退订名单 + 频控三重闸门
- **消息模板**：创建 → 提交审核 → 审核结论（**提交与审核必须不同角色**）→ 渲染发送

## 六、MCP 接入（给 AI 客户端用）

以 stdio 方式启动 MCP 服务：

```bash
pasm-omni --db customer.db serve-mcp
```

在支持 MCP 的客户端（Claude Desktop / Cursor / WorkBuddy 等）中配置该命令即可。
客户端 `initialize` 后可见 **30 个工具**；会造成外部影响的工具需要显式授权。

## 七、验证清单（上线前建议逐项过）

- [ ] 已创建管理员账号 → 确认进入**强制鉴权模式**
- [ ] 未登录状态访问客户列表 / 报表 / 审计 → 应返回 401
- [ ] 挂件在目标站点可正常打开并收发消息
- [ ] 订单 webhook 用**正确签名**能写入、**错误签名**被拒
- [ ] 知识库里至少导入真实 FAQ，并验证「答不上来会转人工」
- [ ] 审计链完整性校验通过
- [ ] 数据库文件已纳入备份策略（单文件，复制即备份）
