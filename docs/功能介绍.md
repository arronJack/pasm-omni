# 功能介绍

> PASM Omni（霖通）· 外接式客户系统内核

---

## 一、渠道层：接到哪里都行

| 渠道 | 接入方式 |
| --- | --- |
| **网页挂件** | 任意站点加一行 `<script src=".../widget.js" data-api="...">`，零前端框架依赖 |
| **Email** | 邮件收发对接 |
| **Telegram** | Bot Token 配置即用 |
| **企业微信** | 自建应用回调（含 AES 加密、签名校验、URL 验证）+ 应用消息主动下发 |
| **外接不限** | 三种姿势：继承 Channel 注册 / 加载第三方包 / 通用 passthrough 外接口 |

**关键点**：渠道是可注册的。想接一个新渠道，不必改内核——渠道层是可替换的，加渠道不改一行核心逻辑。

---

## 二、会话层：一个收件箱管所有渠道

- **统一收件箱**：所有渠道的会话汇到一个工作台，按状态 / 坐席 / 渠道筛选
- **抢单与分配**：坐席领取、转交
- **交接摘要**：转人工时自动生成上下文摘要——客户档案、标签、最近订单、关键对话、内部备注
- **内部备注**：坐席之间可见，对客户不可见，不参与访客侧轮询
- **实时事件流**：新会话、新消息实时推送到工作台

---

## 三、大脑层：可插拔，且默认「不可能幻觉」

大脑层是整个系统里**唯一可插拔**的部分，两种形态共用同一套壳：

| | 抽取式（默认） | PASM 认知引擎（可选） |
| --- | --- | --- |
| 依赖 | **零第三方依赖**（纯标准库） | 需接入 PASM 认知服务 |
| 应答方式 | **直接引用知识库原文**，结构上不可能幻觉 | 检索 + 人格/情绪渲染后生成 |
| 闸门 | 三重：检索面 / 置信度 / 越界 | 四件套：知识选择 / 触面判定 / 语义令牌 / 检索面 |
| 置信度 | 0.00–1.00 精确分值，写入审计 | 框架不暴露逐次分值（诚实显示 n/a） |
| 知识来源 | 内置知识表 | 知识表同步后检索 |

### 默认大脑的核心逻辑

1. **先判越界**：明显与业务无关的问题（问老板是谁、闲聊），直接转人工
2. **再查知识**：命中知识库条目 → **逐字引用原文**答复，不做二次改写
3. **置信度不足** → 转人工，并**写明原因**（是越界、是没命中、还是要人工确认）
4. 全程留痕：每次判定写入审计，可回溯

> 这不是「更聪明的 AI」，是**更安全的 AI**。客服最怕的不是答得不够漂亮，是**答错**。

---

## 四、资产层：SCRM 客户资产

- **客户档案**：跨渠道按稳定标识归一键，同一客户在不同渠道可归并
- **自动标签规则**：入站消息即按规则打标，客户资产自动生长
- **客户分层**：按价值/活跃分层，可筛选
- **访客轨迹**：从落地页到会话的完整时间线（浏览了什么、点了什么、聊了什么）

---

## 五、营销层

- **话术库**：常用话术集中管理，支持分类与检索，坐席一键发送
- **服务评价（CSAT）**：会话结束后访客打分，可统计
- **分流链接**：短码链接，点击计一次，自动 302 到目标页，可按来源统计

---

## 六、数据层

- **实时看板**：会话量、自动答复率、转人工率、首响时间
- **经营报表**：按客户分层 / CSAT 汇总
- **订单统计**：按来源、按状态的订单数与金额汇总

---

## 七、治理层

- **审计 hash 链**：每条动作记录串成哈希链，**改一条即全链暴露**，可用一条命令校验完整性
- **角色权限**：viewer / agent / admin 三级；**审核权与提交权分离**（例如 agent 不能审自己的模板）
- **默认拒绝**：工具级 RBAC 默认拒绝，需要显式授权
- **群发合规闸门**：退订名单、频控、模板审核态，多重约束后才允许群发
- **读写同权**：客户名单、访客轨迹、经营报表、会话列表、知识库、审计日志、实时事件流等
  **读接口与写接口同样要求身份**——避免「功能全对、鉴权全漏」

---

## 八、订单打通（独立站 / 电商）

| 平台 | 支持情况 |
| --- | --- |
| **Shopify** | webhook 免 token、载荷自足，首选 |
| **WooCommerce** | WordPress 电商；物流信息依赖插件写入的元数据 |
| **BigCommerce / Magento / 自建** | 走通用端点，字段别名机制自动识别不同字段名 |
| **其它 / 手工** | CLI 或管理端写入订单，支持 ERP 侧同步 |

**订单能力**：
- 访客问单号 → 秒回**真实状态与物流**（事实驱动，不生成）
- 没给单号但有订单 → 概要最近订单
- **归属校验**：只有订单属于本人（或买家身份一致）才应答，他人单号查不到
- 坐席交接摘要自动携带最近订单

---

## 九、MCP 原生

整个系统以 **30 个 MCP 工具**经 stdio 暴露，支持 MCP 的 AI 客户端（Claude Desktop / Cursor / WorkBuddy 等）
可以直接调用：查会话、回消息、查订单、看报表、管知识库……

工具按风险分级，会造成外部影响的动作（发送回复、群发、改客户资料等）**需要显式授权**才会执行。

## 十、部署与技术特性

| 项 | 说明 |
| --- | --- |
| 运行时 | Python 3.11+ |
| 第三方依赖 | **零**（纯标准库） |
| 数据库 | SQLite 单文件，**幂等迁移**（老库自动升级，不丢数据） |
| 交付形态 | 私有化部署 / 加密分发 + 授权码 |
| 账号模式 | 未配账号 = 兼容模式（**仅限可信网络**）；配了账号 = 强制鉴权模式 |

> ⚠️ **部署前提**：兼容模式（未创建任何账号）下不做鉴权，**只能部署在可信内网**。
> 面向公网请务必先创建账号进入强制鉴权模式。
